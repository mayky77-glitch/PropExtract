# PropExtract

PropExtract — локальная программа для пакетного переноса реквизитов из PDF-разрешений на строительство в реестр Excel. Она распознаёт сканы, группирует версии одного разрешения, переносит подтверждённые значения и сохраняет формулы, стили и встроенную цветовую индикацию сроков.

Все документы обрабатываются на компьютере пользователя. Сервер доступен только по адресу `127.0.0.1` и не отправляет файлы во внешние сервисы.

## Возможности

- загрузка большого набора PDF через путь к папке, включая вложенные папки;
- системные окна выбора папки PDF и целевого Excel без ручного ввода пути;
- OCR сканов на русском и английском языках; одинаковые модели `rus/eng` хранятся в репозитории и проверяются по SHA-256;
- выбор актуальной версии документа по номеру РнС и дате;
- заполнение доступных полей реестра и обновление ссылки на исходный PDF;
- сохранение существующего отличающегося срока с фиксацией конфликта в отчёте;
- проверка формул, стилей, ссылок и правил цветовой индикации перед публикацией;
- автоматическая резервная копия целевого Excel перед заменой;
- JSON-отчёт рядом с обновлённым реестром;
- прогресс обработки и имя текущего документа;
- номера обработанных и отдельно добавленных строк Excel в результате запуска;
- столбец `AA — Статус переноса` с конкретной причиной для неподтверждённых или конфликтующих полей; при полном переносе ячейка пустая;
- светлая и тёмная темы, автоматический выбор по настройкам системы;
- отдельная страница с инструкцией и проверка готовности OCR-компонентов.

## Как работает перенос

1. Программа проверяет папку PDF и целевой файл `.xlsx`.
2. Для PDF с текстовым слоем используется `pdftotext`; сканы рендерятся через Poppler и распознаются Tesseract (`rus+eng`).
3. Документы с одинаковым номером РнС объединяются, выбирается актуальная версия.
4. Изменения записываются во временный Excel. Рабочий файл в этот момент не меняется.
5. Временный файл повторно открывается и проверяется. Затем создаётся резервная копия рабочего Excel.
6. Только после успешных проверок временный файл атомарно занимает место целевого реестра.

Если обработка завершается ошибкой до последнего шага, целевой Excel остаётся прежним.

## Установка в Windows

Поддерживаются 64-битные Windows 10/11. Windows 11 ARM64 поддерживается через встроенную эмуляцию x64 и обязательно проверяется перед первым запуском. 32-битная Windows не поддерживается текущими версиями Tesseract и Poppler.

Откройте командную строку в папке проекта и выполните одну команду:

```bat
install_windows.cmd
```

Можно также дважды нажать `install_windows.cmd` в Проводнике. Скрипт развернёт внутри проекта portable Python 3.12.10, Tesseract 5.5.3 и Poppler 25.07, проверит OCR и запустит PropExtract.

`WinGet`, Microsoft Store, системный Python, сеть и права администратора не нужны. Окно UAC появляться не должно. Все Windows-компоненты и Python-пакеты уже находятся в папке `packages/`. Установщик проверяет SHA-256 каждого исходного архива, собирает runtime во временной папке и до первого запуска сверяет полный хэш всех его файлов с `windows-runtime.lock.json`. При каждом последующем запуске оба дерева — Python и OCR — проверяются заново. Повреждённый или подменённый файл не используется.

Если защитное ПО удалило файл из `.runtime`, просто повторно запустите `install_windows.cmd`: установщик обнаружит повреждение и восстановит Python/OCR из проверенных локальных архивов. Если в карантин попал сам архив из `packages/`, установщик остановится до запуска кода и сохранит журнал `install-windows.log`. Не отключайте антивирус: проверьте его журнал и правила организации, затем заново скачайте проект из GitHub либо согласуйте файл с администратором.

Повторный запуск после установки: `start_windows.cmd`.

Для диагностического запуска без открытия сервера:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install_windows.ps1 -NoStart
```

Установщик намеренно не выполняет сетевых запросов. Если локальный пакет удалён или повреждён, он остановится до запуска кода и попросит заново скачать проект.

## Установка в Linux

Для Ubuntu/Debian и Fedora одна команда:

```bash
./install_linux.sh
```

Если право запуска потерялось после распаковки: `chmod +x install_linux.sh && ./install_linux.sh`. Скрипт сам выберет `apt-get` или `dnf`, установит пакеты, создаст `.venv`, проверит OCR и запустит PropExtract.

Повторный запуск: `./start_linux.sh`.

## Работа в интерфейсе

1. Закройте целевой реестр в Excel или LibreOffice.
2. Нажмите **Выбрать** и укажите папку с PDF в системном окне.
3. Нажмите **Выбрать** у поля Excel и укажите целевой `.xlsx`.
4. Нажмите **Перенести данные** и дождитесь статуса **Готово**.
5. При необходимости откройте JSON-отчёт или резервную копию по путям, показанным на экране.

Служебные столбцы `Y` и `Z` исходного реестра заняты формулами, поэтому статус записывается в первый свободный столбец `AA`. Безопасные различия регистра, пробелов, `ё/е`, Unicode и видов кавычек не считаются конфликтом. Базовый контракт нормализации адаптирован из модуля `report_processor.training_data.normalization` проекта Document Optimizer.

Резервные копии складываются в папку `Резервные копии PropExtract` рядом с реестром. Встроенная страница **Инструкция** содержит краткую памятку оператору.

## Консольный режим

Режим создания отдельного файла, без замены исходного Excel:

```bash
python -m rns_import_server.app process \
  --pdf-dir "/полный/путь/к/pdf" \
  --xlsx "/полный/путь/к/реестру.xlsx" \
  --output "/полный/путь/к/результату.xlsx"
```

Запуск сервера вручную:

```bash
python -m rns_import_server.app serve --host 127.0.0.1 --port 8775
```

## Безопасность данных

- сервер намеренно запрещает внешний сетевой адрес;
- пути-символические ссылки не принимаются для входных документов;
- рабочие PDF не изменяются;
- Excel публикуется через временный файл только после проверок;
- перед заменой проверяется хэш исходного Excel и резервной копии;
- репозиторий исключает PDF, XLSX, отчёты, локальные среды и резервные копии через `.gitignore`;
- Windows-артефакты версионированы и проверяются до выполнения или распаковки;
- Python-зависимости устанавливаются только из локальных wheel-файлов с обязательными SHA-256;
- проект не содержит ключей API, паролей или телеметрии.

## Одинаковый OCR в Windows и Linux

Файлы `rns_import_server/tessdata/rus.traineddata` и `eng.traineddata` входят в Git-репозиторий. PropExtract принудительно передаёт Tesseract путь к этим моделям, а не к языковым файлам операционной системы. Перед запуском сверяются хэши обеих моделей. Модели из [официального репозитория Tesseract](https://github.com/tesseract-ocr/tessdata), лицензия Apache-2.0.

В Windows portable Python 3.12.10, движок Tesseract 5.5.3, его DLL, Poppler 25.07 и app-local Visual C++ Runtime закреплены внутри проекта и не смешиваются с системными версиями. Системное окно выбора файла/папки открывается через встроенный Windows Forms, поэтому отдельный Tkinter не нужен. В Linux используются пакеты дистрибутива, но те же языковые модели. Установщики проверяют все компоненты командой `python -m rns_import_server.runtime`. Полное побайтовое равенство OCR между разными ОС не гарантируется, но Windows-компьютеры используют один и тот же движок и модели.

## Разработка и тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests/test_admin_server.py
```

Основной код находится в `rns_import_server/`: `app.py` управляет импортом, `server.py` — локальными задачами и HTTP, `ocr.py` — OCR, `rns_adapter.py` — правила извлечения, `workbook.py` — безопасная запись Excel.
